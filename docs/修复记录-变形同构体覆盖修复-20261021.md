# 修复记录：变形同构体加强mod 覆盖导致的启动崩溃（2026-10-21）

## 症状

```
file:///D:/weishuxieyi/Stronghold-Protocol-v0.3.0/Stronghold-Protocol/server/match/match/rehearsal.js:25
import { createDelegatedRehearsalJob } from '../bot.js';
         ^^^^^^^^^^^^^^^^^^^^^^^^^^^
SyntaxError: The requested module '../bot.js' does not provide an export named 'createDelegatedRehearsalJob'
```

## 根因

`mod-morph-plus`（变形同构体加强mod 1.1.0）是**面向上游 v0.2.2 的整文件覆盖包**（自带 `manifest.json` 里
`"app": "0.2.2"`）。它于 2026-10-21 07:40 最后安装，用自带的 1818 行 `server/match/bot.js`（0.2.2 基线）
覆盖了本目录 0.3.0 的 `bot.js`。

而 0.3.0 新增了「主机浏览器代跑布阵彩排」：

- `server/match/match/rehearsal.js` 从 `../bot.js` 取 `createDelegatedRehearsalJob`
- `server/match/Match.js`、`server/match/match/prep.js` 依赖它的 `takeOver()` / `onSettled()` 接口

0.2.2 基线的 bot.js 里没有这个导出，ESM 静态链接阶段直接抛错，进程在起服务前退出（exit 1）。

同一个包还一并覆盖了 13 个文件（`bondsMeta.js` / `player/items.js` / `player/acquire.js` /
`support/index.js` / `support/meta.js` / `invariants.js` / `bot.js` + 6 个前端文件），
把 0.3.0 的改动一起退回了 0.2.2 —— 只修 bot.js 会让其余文件继续带着旧代码跑。

## 处理

把这 14 个被覆盖的文件恢复成 `mod-fanpack`（整合包 v1.6.0-适配0.3.0）payload 里的版本。
整合包已经把「变形同构体」这套规则移植到了 0.3.0，不需要再叠 0.2.2 的覆盖包：

没有。逐个文件比对过 6 个服务端文件里与变形同构体相关的行（`isMorphItem` / `morphGrants` /

## 注意

**不要在 0.3.0 上再安装 `mod-morph-plus` 1.1.0**，它就是给 0.2.2 做的整文件覆盖包；
整合包 `mod-fanpack` 已经内含这套规则。若用 mod 管理器再装一次，本崩溃会原样复现
（管理器还可能把它记成「已安装」，重装前请先在管理器里卸载 / 忽略该包）。

同目录下的 `mod-morph-plus\mod-manifest.json` 仍是那次安装留下的记录，它现在不代表真实文件状态，
留作溯源用，不要对它执行 `install.mjs --uninstall`——那会把文件退回到纯净 0.3.0，丢掉整合包的改动。
